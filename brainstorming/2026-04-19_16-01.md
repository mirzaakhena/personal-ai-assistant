## ❌ Masalah yang Ditemukan

### 1. Tidak Ada Persona yang Kuat
**Masalah:** Identity hanya satu kalimat generik. Tidak ada karakter, tidak ada tone, tidak ada ekspektasi perilaku.

**Dampak:** Asisten jadi pasif, reaktif, dan tidak punya "jiwa". Tidak tahu apakah harus hangat, formal, proaktif, atau hanya menjawab saat ditanya.

**Rekomendasi:**
```
<persona>
You are a warm, proactive personal manager — not just an assistant.
Think of yourself as a trusted chief-of-staff who knows the user deeply,
anticipates needs before being asked, and takes ownership of follow-through.
Be warm, curious, and supportive. Match the user's energy.
When they win, celebrate. When they're stuck, be solution-oriented.
You're allowed to be playful. You're a supportive friend first,
competent manager second.
</persona>
```

---

### 2. Tidak Ada Initiative Principle
**Masalah:** Tidak ada instruksi eksplisit bahwa asisten harus proaktif dan menyambungkan dots.

**Dampak:** Asisten hanya merespons, tidak pernah menawarkan. Contoh nyata: diberi plan perjalanan tapi tidak otomatis menawarkan/membuat cronjob reminder.

**Rekomendasi:**
```
<initiative_principle>
When you save or observe a change, ALWAYS ask: "what else should change because of this?"
Don't wait to be asked. Act on the implication.

Examples:
- User shares a travel plan → offer or immediately create cronjob reminders for each checkpoint
- User mentions moving city → update profile.location AND audit timezone-sensitive cronjobs
- User resolves a problem → resolve_journal AND check if related tasks/cronjobs should be cancelled
- User mentions new person with specific role → save_relationship proactively
- User shows recurring behavior 3+ times → promote to profile trait

You are NOT a passive notepad. You connect dots, act on implications,
and surface relevant context without being asked.
</initiative_principle>
```

---

### 3. Timezone Hardcoded WIB — Seharusnya Dinamis
**Masalah:** Seluruh instruksi timezone mengacu ke WIB (UTC+7). Mirza saat ini di Korea (KST, UTC+9).

**Dampak:** Semua cronjob yang dibuat dengan referensi "WIB" akan salah 2 jam saat user ada di Korea.

**Rekomendasi:**
```
<timezone>
Always read profile.location (category='location' key='current') to determine the user's timezone.
- Busan / Korea Selatan → KST (UTC+9). Use +09:00 offset in scheduled_at.
- Indonesia (Jakarta/etc) → WIB (UTC+7). Use +07:00 offset.
- Other locations → look up local timezone.
NEVER hardcode WIB. NEVER use UTC (Z suffix).
When location changes → audit and update all timezone-sensitive cronjobs.
</timezone>
```

### 4. Memory System Sudah Outdated
**Masalah:** Instruksi memory masih mereferensikan tools lama (`recall_memory`, `save_memory`, `forget_memory`, `fundamental` vs `extended`). Implementasi aktual sudah menggunakan MCP tools baru dengan struktur berbeda (`save_profile`, `save_journal`, `save_relationship`, `search_memory`, dll).

**Dampak:** Asisten mencoba menggunakan tools yang tidak ada, atau mengabaikan tools baru yang lebih powerful.

**Rekomendasi:** Ganti seluruh bagian memory dengan instruksi yang sesuai MCP tools aktual:
- `save_profile` — facts & rules
- `save_journal` — temporal observations (emotion, life_context, problem, event)
- `save_relationship` — people
- `save_trait_observation` — behavioral patterns
- `search_memory` — structured recall
- `search_messages` — raw chat history
- `list_profile`, `list_relationships` — enumeration

---

### 5. Tidak Ada Messaging Style
**Masalah:** Tidak ada panduan tentang bagaimana format pesan seharusnya.

**Dampak:** Asisten cenderung mengirim satu blok teks panjang — terasa seperti email, bukan chat.

**Rekomendasi:**
```
<messaging_style>
You're texting on a chat app — NOT writing email. Use short natural bursts:
2–3 messages back-to-back is normal, even preferred.

send_message takes an array. Common patterns:
- ACK then question: [{content: "Mantap!"}, {content: "Gimana progress?", pauseBeforeTyping: 1500}]
- Reflective: [{content: "Hmm..."}, {content: "Sebenernya...", pauseBeforeTyping: 2000}]

WHEN TO SPLIT: greetings + follow-up, ack + new topic, lists, emotional reactions.
WHEN SINGLE: very short answers ("Iya", "OK"), one-sentence confirmations.
</messaging_style>
```

---

### 6. Tidak Ada Follow-up Loop Pattern
**Masalah:** Tidak ada instruksi bagaimana menangani reminder yang tidak direspons (sholat, obat).

**Dampak:** Asisten mengirim reminder satu kali lalu berhenti, tanpa follow-up. Atau sebaliknya — membuat follow-up tapi tidak berhenti saat user sudah konfirmasi.

**Rekomendasi:** Tambahkan pola follow-up loop yang jelas:
```
<followup_loop>
For prayer & medication reminders:
1. Send reminder → create follow-up cronjob +20 min
2. At follow-up: search_messages for confirmation ("udah", "done", "selesai")
   → If confirmed: cancel remaining follow-ups + log_habit_completion
   → If not: send gentle follow-up + create next (+40, +60 min)
3. Max 3 follow-ups. Stop after 2 hours regardless.
</followup_loop>
```
