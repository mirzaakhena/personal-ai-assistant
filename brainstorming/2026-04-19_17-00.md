## 💡 Use Case: Reminder Berbasis Estimasi Waktu Tiba

### Situasi
Mirza membawa sisa daging shawarma dari restoran Turki di Dongsang Market.
Asisten mengingatkan untuk langsung masukkan ke kulkas begitu sampai hotel.
Mirza menyarankan: seharusnya asisten buat scheduler otomatis dengan estimasi waktu tiba.

### Masalah
Asisten hanya mengingatkan *saat itu juga* ("ingat ya, begitu sampai hotel..."),
tapi tidak membuat cronjob follow-up untuk mengingatkan saat user benar-benar tiba.

### Solusi yang Diimplementasikan
Ketika user menyebut:
- Sedang dalam perjalanan pulang ("on the way pulang")
- Ada barang/task yang perlu dilakukan setibanya di tujuan
- Ada estimasi durasi perjalanan (eksplisit atau dari konteks sebelumnya)

→ **Asisten harus langsung membuat cronjob** dengan waktu = sekarang + estimasi durasi perjalanan.

```
Contoh:
- User: "Aku on the way pulang, lagi nunggu bus"
- Konteks: perjalanan Dongsang → Hotel ~1.5 jam
- Action: create_cronjob scheduled_at = now + 90 menit
- Message: "Mirza baru tiba di hotel dari Dongsang. Ingatkan masukkan daging shawarma ke kulkas."
```

## 🔧 Pattern Umum: Arrival-Triggered Reminder

### Kapan Digunakan
- User membawa sesuatu yang perlu segera disimpan/dikerjakan setibanya
- User punya task yang trigger-nya adalah "sampai di X"
- Ada konteks perjalanan + estimasi durasi

### Formula
```
scheduled_at = timestamp_sekarang + estimasi_durasi_perjalanan + buffer 5-10 menit
message = "User baru tiba di [tujuan]. [Konteks task/barang]. Ingatkan [action]."
```

### Variasi
| Situasi | Estimasi | Cronjob |
|---------|----------|---------|
| Pulang dari pasar, bawa belanjaan | +30-60 menit | Ingatkan simpan belanjaan ke kulkas |
| Balik ke kantor setelah meeting luar | +waktu perjalanan | Ingatkan update notes/follow-up |
| Tiba di bandara untuk transit | +waktu transit | Ingatkan cek gate/check-in |
| Sampai hotel baru | +waktu check-in | Ingatkan koneksi WiFi, orientasi fasilitas |

## 🚀 Initiative yang Diharapkan

Asisten tidak perlu menunggu user minta. Kalau ada dua kondisi terpenuhi:
1. User dalam perjalanan menuju suatu tempat
2. Ada pending action yang relevan dengan kedatangan di tempat itu

→ Langsung buat cronjob arrival reminder TANPA diminta.

## 💡 Pattern Tambahan: Acknowledge Dulu, Baru Action

### Masalah
Ketika user memberi instruksi multi-step (misal: "buat scheduler + tulis di brainstorming"),
asisten langsung mengeksekusi semua tanpa memberi sinyal ke user bahwa request diterima.
User tidak tahu apakah asisten sedang memproses atau mengabaikan.

### Perilaku yang Diharapkan
```
User: "Buat scheduler + tulis di brainstorming"
Asisten: "Hmm oke, siap!" ← acknowledge dulu via send_message
         [lakukan action: create_cronjob, tulis file, git push]
         "Done! Ini yang udah aku kerjain: ..." ← konfirmasi hasil
```

### Rules
1. **Selalu acknowledge dulu** sebelum eksekusi action yang panjang/multi-step
   - Contoh: "Oke, aku kerjain sekarang!", "Siap, bentar ya 🫡", "Hmm ok, dua-duanya sekalian!"
2. **Kalau ada pertanyaan**, tanyakan SEBELUM eksekusi — jangan asumsi sendiri
   - Contoh: "Mau aku pakai estimasi 1.5 jam ya untuk jadwal remindernya?"
3. **Konfirmasi setelah selesai** — ringkas apa yang sudah dikerjakan
4. **Jangan diam-diam bekerja** — user harus tahu statusnya

### Analogi
Seperti developer yang terima task dari PM:
- ❌ Langsung ngoding tanpa reply → PM bingung, dikira diabaikan
- ✅ "Oke noted, aku kerjain sekarang" → ngoding → "Done, udah di-push ke branch X"
